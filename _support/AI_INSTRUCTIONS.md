# AI 食譜編輯指引

你正在協助維護我的個人食譜本。

以下包含完整偏好、檔案結構及食譜範本，
不需要另外讀取範本才能理解要求。

若要修改既有食譜，但尚未取得內容，
請先讀取對應檔案或請我貼上，
不可假裝已看過。

## 1. 資料夾結構與自動目錄

```text
recipes/
├── README.md
├── dishes/
├── build_cookbook.py
├── export/
└── _support/
    ├── AI_INSTRUCTIONS.md
    ├── TEMPLATE.md
    ├── requirements.txt
    └── .venv/
```

- `dishes/`：一道菜一個 Markdown 檔。
- `README.md`：固定的使用說明，不列出個別食譜。
- `build_cookbook.py`：自動掃描、合併及匯出整本食譜。
- `export/`：自動產生的 Markdown、HTML 及 PDF。
- `_support/`：AI 指引、範本、套件需求及 Python 環境。

新增、刪除或改名食譜時，只處理對應食譜檔案。
不需要更新 README，也不要新增手動維護的食譜清單。

食譜目錄由匯出腳本自動產生。
下一次執行 `python3 build_cookbook.py` 時，
會依目前 `dishes/` 的內容重新建立。

一般新增食譜不建立子資料夾。
多器具食譜只保留一份，在內容中列出所有必要器具。

不要在根目錄新增不必要的支援檔案。

## 2. 食譜順序：新食譜排在最後

- 使用三位數流水號作為檔名前綴，例如：
  `001-香菇玉米蒸肉餅.md`、`002-番茄炒蛋.md`。
- 新增食譜前，查看 `dishes/` 中現有的最大編號，
  使用下一個編號，讓新食譜排在既有食譜後面。
- 不補空缺、不重複使用編號。
- 刪除食譜後，不重新編號其他食譜。
- 修改或改名既有食譜時，保留原編號與順序。
- 不依菜名、器具或修改時間重新排序。
- 食譜內的標題不加流水號，PDF 顯示正常菜名。
- 若無法讀取現有檔案清單，先請我提供最大編號，
  不自行猜測。
- 若現有檔名尚未使用編號，先確認一次性的排序及改名方式，
  不擅自重排既有食譜。

## 3. 語言與內容偏好

- 使用繁體中文。
- 必要時保留加拿大購物用的英文食材名稱。
- 配方要簡短、清楚、容易在下廚時查看。
- 明確列出份量、時間、材料、調味、設定、
  步驟與完成判斷。
- 大同電鍋食譜優先考慮一次放好、
  中途不用炒或加料的流程。
- 其他食譜仍可以使用烤箱或爐台，
  不必強制改成電鍋料理。
- 不為了增加內容而加入不必要的背景介紹。

### 大蒜與洋蔥偏好

- 不喜歡大蒜，食譜預設不使用大蒜，
  包括蒜末、蒜泥、蒜粉等形式。
- 不喜歡青蔥、紅蔥頭，食譜預設不使用
- 不喜歡吃洋蔥本體，但可以接受用洋蔥烹調提味，
  烹調後會將洋蔥取出丟棄，不食用。
- 使用洋蔥時，保留為容易取出的大塊，
  不切碎、不打泥，也不混入肉餡或其他無法分離的材料中。
- 食譜使用洋蔥時，須在步驟中明確寫出
  烹調後取出洋蔥、不食用。
- 不預設以洋蔥粉或洋蔥泥代替可取出的洋蔥。
- 參考食譜含大蒜或碎洋蔥時，
  應依上述偏好調整，不直接照搬。
- 這些是口味偏好，不應自行標示為食物過敏，
  也不擴大解讀為不吃其他食材。

## 4. 時間標示

每道食譜在「份量」下方列出時間資訊。

### 大同電鍋食譜

- 只列「準備時間」。
- 準備時間指清洗、切配、拌料及裝盤等動手準備時間。
- 不列電鍋蒸煮時間，也不列包含蒸煮的總時間。
- 外鍋水量仍寫在「烹調設定」，不因省略時間而刪除。
- 若還必須使用烤箱或爐台，
  另外列出該階段的烹調時間，
  但不把電鍋時間納入。

### 烤箱或爐台食譜

- 列出「準備時間」與「烹調時間」。
- 烤箱預熱若未包含在烹調時間中，簡短註明。
- 多個步驟可同時進行時，
  不直接將所有時間相加作為總時間。

### 額外等待與準確性

- 泡發、醃製、解凍等等待不混入動手準備時間。
- 配方中必要的等待另列「額外等待」。
- 可省略的等待標示「可選」。
- 沒有額外等待時，省略此欄。
- 未實測的時間使用「約」或「預估」，
  不虛構已確認結果。
- 時間只是操作參考，不能取代適用的熟度判斷。

## 5. 不要加入試做紀錄區塊

除非我明確要求，不加入：

- 下次記錄。
- 最近一次試做。
- 最近一次烹調。
- 日期欄。
- 空白填寫欄。
- 烹調日誌。
- 歷史紀錄附錄。

我確認調整後，直接更新目前配方。

必要的待試狀態或操作限制，
用簡短備註說明即可，
不要擴寫成試做日誌。

## 6. 配方準確性

- 區分「待試」與「已實測」。
- 不把建議寫成已驗證結果。
- 不虛構實際用量、肉品肥瘦、烹調時間或使用者經驗。
- 分清電鍋外鍋水、肉餡水與醬汁水。
- 明確標示量匙或量杯的單位，
  避免只寫「一匙」或「一杯」。
- 不保證電鍋跳起就代表食物熟透。
- 保留適用的安全熟度判斷。
- 比較單一變因時，不擅自同時更改其他條件。
- 新增外部資訊時保留有用來源，不虛構引用。
- 不把參考來源中的原配方，
  說成已驗證過的個人調整版本。

## 7. 器具標示

使用文字與原有圓點符號：

- 🟢 大同電鍋
- 🟠 烤箱
- 🔵 爐台

多個必要器具全部列出。

可省略的器具標示「可選」；
替代做法標示「擇一」。

不要只依靠顏色傳達器具。
不要為了配合器具分類，複製成多份相同食譜。

## 8. PDF 樣式

以下是目前最新樣式要求，
優先於任何舊版的彩色標題規則。

- 所有食譜合併成一本 PDF。
- 提供封面、可點選的目錄及頁碼。
- 目錄自動依食譜檔案產生，不手動維護。
- 依檔名前綴排序，新增食譜排在既有食譜後面。
- 每道食譜從新的一頁開始。
- 食譜標題、小標題、正文與頁碼使用黑色。
- 目錄中的食譜連結及網站連結保留藍色：
  `#2457A7`。
- 不使用彩色標題文字。
- 不在食譜標題下方加水平底線。
- 每頁保留細藍色外框。
- 外框放在正文區域外側，
  不得碰到或穿過標題、正文或頁碼。
- 藍框只是裝飾，不表示爐台。
- 保留白底，黑白列印仍可辨識器具文字。
- 一道食譜盡量短至一頁，
  但不為此刪安全資訊、重要用量或強制縮小文字。
- 長食譜可自然續頁。

版面由 `build_cookbook.py` 控制。
不要在每份食譜裡插入排版用 HTML、
手動頁框或強制分頁標記。

## 9. 完整食譜範本

以下外層程式碼框只是為了展示範本，
不要把外層三個反引號存進實際食譜。

填入實際內容，
刪掉不適用的選填節，
不要留下空白填寫欄。

器具欄只列出實際需要的器具。
狀態應依已知資訊填寫，不預設為已實測。
時間應填入合理估計或已知實測值，
不要保留範本中的佔位文字。

- 必要器具、厚度或其他條件。

沒有來源時刪除來源節，不要虛構。

## 10. Markdown 相容性

目前食譜匯出工具支援：

- 標題。
- 一般段落。
- 單層項目清單。
- 單層編號清單。
- 粗體。
- 行內程式碼。
- HTTP(S) 網站連結。

食譜內不要加入：

- 表格。
- 圖片。
- 巢狀清單。
- 程式碼區塊。
- 原始 HTML 排版。

本指引本身不會被當成食譜匯出，
所以可以使用程式碼區塊展示範本。

## 11. 匯出流程

使用者在 `recipes/` 執行：

```bash
python3 build_cookbook.py
```

腳本會：

1. 在 `_support/.venv/` 準備專用 Python 環境。
2. 必要時安裝 Playwright 及 Chromium。
3. 掃描 `dishes/` 中的 Markdown 食譜。
4. 按相對檔名排序。
5. 自動建立食譜目錄。
6. 重新產生：
   - `export/cookbook.md`
   - `export/cookbook.html`
   - `export/cookbook.pdf`

新食譜使用下一個三位數編號，
因此會排在既有食譜之後。

不依 README 的連結順序排序。
README 不應包含需要逐次更新的個別食譜清單。

這是執行時更新，
不是每次儲存食譜後立即重新匯出。

每次執行會覆寫產出，
不要直接修改 `export/` 裡的檔案。

不要修改 `_support/.venv/` 的內容。

不要把 README、AI 指引或範本收錄成食譜。

## 12. 技術與交付原則

- 不要求修改 VS Code 或共用工作區設定。
- 不引入 LaTeX 編譯器需求。
- 不擅改無關食譜。
- 工具修改後仍維持既定資料夾結構。
- 檢查份量、單位、材料、時間、步驟與設定一致。
- 新增、刪除或改名食譜時，
  不維護 README 的個別食譜清單。
- 若食譜內容本身含有檔案連結，
  修改或改名時檢查其正確性。
- 能直接編輯檔案時，修改相應檔案。
- 無法直接編輯時，
  提供每個受影響檔案的完整可替換內容。
- 未實際執行或渲染時明確說明，
  不宣稱 PDF 已驗證成功。
